# Rejestr decyzji produktowych (DEC)

**Stan:** `BASELINED`, 2026-10-27. **Źródło akceptacji:** właściciel produktu — zatwierdzony baseline przekazany w zadaniu bootstrap. Każde `APPROVED` odnosi się do *zakresu opisanego w tym wierszu*, nie do wszystkich jego domniemanych konsekwencji.

| ID | Status | Treść decyzji (normatywna) |
|---|---|---|
| DEC-001 | APPROVED | Sprawa rekrutacyjna to centrum produktu; nie utożsamiać jej z firmą ani ogłoszeniem. |
| DEC-002 | APPROVED | Sprawa obsługuje ofertę zapisaną, aplikację, spontaniczną kandydaturę, kontakt inbound i outbound również bez wysłanego CV. |
| DEC-003 | APPROVED | Jedna organizacja może mieć wiele niezależnych spraw. |
| DEC-004 | APPROVED | Dokładnie cztery statusy ogólne: Zapisane, Kontakt rozpoczęty, W rekrutacji, Zakończone. |
| DEC-005 | APPROVED | Bez statusu Wstrzymane. |
| DEC-006 | APPROVED | „W rekrutacji” oznacza zaproszenie do konkretnego etapu kwalifikacyjnego; wysłanie CV/potwierdzenie aplikacji nie wystarcza. |
| DEC-007 | APPROVED | Status ogólny i szczegółowy etap rekrutacji to odrębne pojęcia. |
| DEC-008 | APPROVED | Domyślne, globalnie personalizowane i indywidualne etapy; można pomijać etapy, historia zmian pozostaje. |
| DEC-009 | APPROVED | Zmiany statusu przede wszystkim przez akcje biznesowe; ręczna korekta nie wytwarza fikcyjnego zdarzenia. |
| DEC-010 | APPROVED | Zamknięcie wymaga wyniku; zakończenia historyczne pozostają. |
| DEC-011 | APPROVED | Brak odpowiedzi nie zamyka spraw automatycznie. |
| DEC-012 | APPROVED | Można wznowić sprawę; poprzednie zamknięcia nie znikają; kolejna rekrutacja może być nową sprawą. |
| DEC-013 | APPROVED | Zamykanie sprawy wymaga rozstrzygnięcia otwartych zadań/wydarzeń: anulowanie, zachowanie lub odłączenie. |
| DEC-014 | APPROVED | Wiele uporządkowanych URL-i przy sprawie (ogłoszenie, publikacje, formularz, strona, profil, korespondencja). |
| DEC-015 | APPROVED | Źródło znalezienia i kanał faktycznej aplikacji to różne informacje; link do rozmowy nie udziela dostępu do jej treści. |
| DEC-016 | APPROVED | Dashboard jest operacyjny (uwaga, terminy, sugestie, aktywność, statystyki); bez listy ostatnich rekrutacji i pełnego Kanbana. |
| DEC-017 | APPROVED | Główne moduły: Dashboard, Rekrutacje, Zadania, Kalendarz, Dokumenty, Firmy, Kontakty; wyszukiwanie i Quick Capture globalne. |
| DEC-018 | APPROVED | Dashboard po zalogowaniu; brak obowiązkowego onboardingu. |
| DEC-019 | APPROVED | Rekrutacje: domyślny Kanban, alternatywna lista, 4 statusy, indywidualne etapy na kartach, zwijane Zakończone, filtry/sortowanie/szybkie widoki. |
| DEC-020 | APPROVED | Szczegóły: szybki drawer i pełna strona z centralną osią czasu i sekcjami kontekstowymi. |
| DEC-021 | APPROVED | Małe kontekstowe przyciski dodawania; krótkie formularze inline, bardziej złożone w dialogach; osobne akcje cyklu życia. |
| DEC-022 | APPROVED | Jedna chronologiczna historia sprawy po dacie faktycznego zdarzenia, odróżnionej od daty zapisu; korekty nie tworzą fałszywej aktywności. |
| DEC-023 | APPROVED | Wydarzenie może być przełożone, odbyte, anulowane, nieodbyte; dodanie odbytej rozmowy bez planowania. |
| DEC-024 | APPROVED | Termin w przeszłości nie oznacza odbycia; dla nierozliczonego zdarzenia proponuj potwierdzenie. |
| DEC-025 | APPROVED | Jedno wydarzenie może mieć wielu uczestników. |
| DEC-026 | APPROVED | Zadania mogą być ogólne lub powiązane ze sprawą, z tytułem, opcjonalnym terminem, opisem i statusem. |
| DEC-027 | APPROVED | Przypomnienia w aplikacji; opcjonalny e-mail; bez początkowego push. |
| DEC-028 | APPROVED | Sugestie regułowe bez AI; sugestia nie jest zadaniem; system nie wysyła wiadomości ani nie zamyka spraw samodzielnie. |
| DEC-029 | APPROVED | Quick Capture: dodawanie ręczne, jeden URL Smart Import lub CSV/XLSX z weryfikacją przed zapisem. |
| DEC-030 | APPROVED | Przy nieudanym Smart Import umożliw ręczne dodanie zamiast blokować zapis. |
| DEC-031 | APPROVED | Potencjalne duplikaty wykrywaj, nie scalaj automatycznie; aktualizacja istniejącej sprawy tylko po świadomym wyborze. |
| DEC-032 | APPROVED | Po „Zapisz” zostań w aktualnym widoku; „Zapisz i dodaj kolejną” umożliwia kolejny wpis. |
| DEC-033 | APPROVED | Import własnych CSV/XLSX i gotowego szablonu; mapowanie kolumn/statusów/etapów/wyników. |
| DEC-034 | APPROVED | Podgląd i walidacja importu przed zatwierdzeniem, z identyfikacją błędów i duplikatów. |
| DEC-035 | APPROVED | Częściowy import tylko po wyraźnym potwierdzeniu; można pominąć błędne wiersze. |
| DEC-036 | APPROVED | Raport pominiętych rekordów i powodów; nie twórz brakujących dat ani historii. |
| DEC-037 | APPROVED | Ochrona przed przypadkowym ponownym importem; historyczne rekordy bez automatycznego generowania zaległych sugestii. |
| DEC-038 | APPROVED | Global Search obejmuje sprawy, stanowiska, firmy, kontakty, URL-e, notatki i opisy wydarzeń; wyniki grupowane wg typu. |
| DEC-039 | APPROVED | Biblioteka wielokrotnego użytku i załączniki należące do konkretnej sprawy. |
| DEC-040 | APPROVED | Wersjonowanie CV i możliwość wskazania konkretnej wysłanej wersji; powiązanie ≠ wysłanie. |
| DEC-041 | APPROVED | Dodawanie dokumentu: z biblioteki, tylko do sprawy albo do biblioteki. |
| DEC-042 | APPROVED | Lekka centralna baza organizacji i kontaktów; rozróżnienie pracodawcy, agencji i rekrutera, nie zawsze znany pracodawca. |
| DEC-043 | APPROVED | Kontakt w wielu sprawach, wiele osób w sprawie, profil firmy z powiązaniami, historia kontaktu wyłącznie z faktów powiązanych. |
| DEC-044 | APPROVED | Kontakt bez sprawy jest dozwolony; zapis komunikacji wymaga powiązania ze sprawą. |
| DEC-045 | DEFERRED | AI Career Agent i infrastruktura autonomicznych agentów poza początkowym MVP; przyszłą możliwość zachowujemy koncepcyjnie. |
| DEC-046 | APPROVED | Start dla własnych potrzeb, segment IT/digital, Polska; opcja przyszłego ekspansywnego SaaS. |
| DEC-047 | APPROVED | Publiczne wydanie pełniejsze niż Kanban-demo; wdrażanie etapami wewnętrznie. |
| DEC-048 | APPROVED | Bez formalnych badań respondentów; monetyzacja niezatwierdzona i nie jest obecnym priorytetem. |
| DEC-049 | DEFERRED | Własne zapisywane konfiguracje filtrów, rozszerzenie przeglądarki i wiele URL-i jednocześnie poza MVP. |
| DEC-050 | DEFERRED | Semantyczne wyszukiwanie, indeksowanie zawartości dokumentów i powiadomienia push poza początkowym wydaniem. |
| DEC-051 | APPROVED | PO 2026-10-29, zadanie „Jobs CRM — Supabase-native Architecture Rebaseline”: wariant A — Supabase-native Auth/SSR, e-mail/hasło + Google OAuth/PKCE, samoobsługowa rejestracja, reset hasła e-mailem i sesje wielourządzeniowe. Logout `local/global/others`; bez wymogu zakończenia dowolnej wskazanej innej sesji, HttpOnly-only, własnego brokera ani natychmiastowej nieważności wydanych JWT. Data API + RLS oraz natywne transakcje PostgreSQL/minimalne RPC zachowują prywatność i ADR-0005. Szczegóły sesji, aktywacji i operacji wrażliwych pozostają OPEN. Formalny kontrakt: [ADR-0012](adr/0012-supabase-native-auth-sessions-rls.md). Zadanie autoryzuje dokumentację i PR; nie implementację Auth/RPC. |

## Granice zatwierdzenia

Słownik wyników zamknięcia, nazwy etapów, walidacje, limity, szczegółowe polityki retencji i progi czasu pozostają w [rejestrze OPEN](open-questions.md). Wybory techniczne są utrwalone w [zaakceptowanych ADR](adr/README.md); DEC-051 zapisuje późniejszą decyzję PO, bez zatwierdzania pozostałych polityk ani pełnych kontraktów Account Management.
